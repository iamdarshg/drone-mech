# Phase-15 wing-sector boundary audit and refined mesh sensitivity

## Boundary audit

The `gmshToFoam` message “Found 5,464 undefined faces ... adding to default patch defaultFaces” is a staging warning for the boundary faces before physical groups are applied. It does not indicate missing physical boundary labels in the resulting mesh.

The tracked MSH2 file has all six expected physical names: volume `fluid` (tag 1) and surfaces `inlet` (11), `outlet` (12), `farfield` (13), `fsi` (14), `rootWall` (15). Counting its Gmsh type-2 triangle elements gives, in that surface order, 150, 150, 1,338, 3,526, and 300 triangles: 5,464 total. OpenFOAM `checkMesh` reports the same final named-patch face counts. The converted `constant/polyMesh/boundary` has only those five patches and no `defaultFaces`. These results rule out missing named surface patches as a cause of the solver instability.

Source evidence: `/workspace/drone-mech/highspeed_edf/phase15/optimization/phase15_fsi_casegen.py`, especially `fluid_mesh()` and `set_mesh_fields()` (boundary partition, physical groups, mesh parameters). The native original conversion log is `../../raw/logs/gmshToFoam.log`; original mesh check is `../../raw/logs/checkMesh.log`.

## Refined mesh

`generate_refined_mesh.py` locates the repository root from its own path, imports the tracked Phase-15 case generator, and builds the same 30 mm outboard wing-sector geometry and farfield box. It halves the generator's 12/120 mm `MeshSizeMin/Max` values to 6/60 mm while keeping its curvature sampling, distance field thresholds, algorithms, and normal Gmsh optimization. Regenerate with Python Gmsh 4.15.2 installed from the pinned PyPI wheel and `PYTHONPATH=/tmp/phase15-gmsh`; the wheel's Python binding links to its bundled Gmsh 4.13.1 library (`gmshPythonBinding=4.15.2`, `General.Version=4.13.1`, SONAME `libgmsh.so.4.13`). The runtime reports Netgen optimization unavailable, so `Mesh.OptimizeNetgen` is disabled; `Mesh.Optimize` remains enabled. This local-library difference is part of the experiment and limits a strict mesh-only comparison. `provenance.json` records the binding/runtime versions and SHA256 hashes of the source generator, regeneration script, tracked base mesh, and refined output mesh. The generated fluid MSH2 hash is `75bb3b5fcb3eac8893eb737af0125ea37e397ebba90db53a322dfdb2ea45274b` and regenerated byte-for-byte with the documented runtime.

The generated wing and fluid volumes are 0.0012773004678969851 m³ and 1.5601048211505963 m³, respectively; the domain bounds are unchanged. The source mesh has 34,166 fluid tetrahedra; the refined mesh has 258,681 (7.57x) and 45,665 points. The refined mesh preserves all five named groups. `gmshToFoam` reports 17,286 undefined staging faces, exactly the sum of the five physical triangle counts and final OpenFOAM patch counts. The final `checkMesh` reports Mesh OK.

| Native quality measure | Tracked mesh | Refined mesh |
|---|---:|---:|
| Cells | 34,166 | 258,681 |
| Maximum aspect ratio | 16.31 | 11.15 |
| Minimum cell volume (m³) | 2.507e-10 | 6.686e-10 |
| Maximum non-orthogonality | 82.87° | 77.48° |
| Average non-orthogonality | 17.10° | 20.86° |
| Faces above 70° | 50 | 42 |
| Maximum skewness | 1.223 | 1.484 |

The refinement improved the maximum aspect ratio, minimum volume, maximum non-orthogonality, and count of severely non-orthogonal faces; average non-orthogonality and maximum skewness worsened. This is not a uniformly better-quality mesh and no grid convergence claim is made.

## Bounded compressible checks

The OpenFOAM `rhoPimpleFoam` cases use the same native IAS700 (222.132204 m/s) and IAS900 (283.172 m/s) fields, source solver dictionaries, and maxCo 0.4 as the original packaged transient cases. Both `-dry-run` checks passed. Wall-capped 20 s native runs ended by SIGINT with timeout status 124, without solver fatal errors or normal `End` markers:

- IAS700 reached 5.14156e-6 s, with final deltaT 4.24535e-7 s and max Courant 0.4009.
- IAS900 reached 4.36062e-6 s, with final deltaT 3.31120e-7 s and max Courant 0.4012.

These short runs are much less physically advanced per wall time because the refined mesh has 7.57x as many cells. They do not establish whether the original late local timestep collapse is fixed, and produce no usable aerodynamic or convergence result. No coefficients, shock position, or design ranking are inferred.

Native logs: `gmshToFoam_native.log`, `checkMesh_native.log`, `dryrun_ias700.log`, `dryrun_ias900.log`, and `rhoPimpleFoam_ias700_bounded.log` / `rhoPimpleFoam_ias900_bounded.log`. `regeneration.log` records a second exact regeneration using the relative-path script and pinned Gmsh runtime; it produced the same output mesh hash. Regeneration is isolated to this experiment; the tracked source mesh and packaged baseline cases were not modified.

## Reproduction commands

From the repository root:

```sh
python3 -m pip install --target /tmp/phase15-gmsh gmsh==4.15.2
PYTHONPATH=/tmp/phase15-gmsh \
  python3 highspeed_edf/phase15/fsi/results/local_openfoam_20261030/experiments/generate_refined_mesh.py
```

The script also works when invoked by absolute path from another current directory; it locates the repository by walking its own parent directories. It calls the source generator’s fluid-mesh path only and writes the MSH2, result summary, and provenance into its adjacent `mesh_refine2x/` folder. The OpenFOAM import case links to that one generated MSH file. The temporary Gmsh install is not vendored or needed at runtime for the recorded OpenFOAM runs. The second generation was invoked from `/tmp` and emitted the same fluid mesh SHA256; see `regeneration_portable.log`.

The recorded native import used Debian OpenFOAM 1912.200626-3+b1 from `/workspace/openfoam-deb`. The imported mesh case is `ias700/`; `ias900/constant/polyMesh` points to the same imported mesh. The original and refined Gmsh meshes remain available in this folder for repeat imports.
