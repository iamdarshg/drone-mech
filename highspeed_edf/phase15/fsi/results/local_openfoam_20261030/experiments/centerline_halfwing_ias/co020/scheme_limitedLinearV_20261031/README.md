# Isolated velocity-convection scheme sensitivity

This fresh-from-zero sensitivity changes exactly one numerical factor from `localization_20261031`: `div(phi,U)` uses `bounded Gauss limitedLinearV 1` instead of `bounded Gauss upwind`. This is a bounded limited-linear alternative to the baseline's more diffusive first-order upwind velocity convection. All other schemes, the transonic PIMPLE configuration, maxCo=0.2, initial/max time step, mesh, fields, and 10-step write interval are held fixed. `rhoPimpleFoam -dry-run` succeeded for both IAS700 and IAS900. Each run then used a 180 s wall cap and exited 124 without a normal `End` marker.

At the closest common checkpoint to 10 microseconds, the baseline and limited-linear results are very similar: IAS700 max speed 258.72 vs 258.13 m/s and max pressure 88.779 vs 88.752 kPa; IAS900 max speed 323.77 vs 323.63 m/s and max pressure 94.482 vs 94.374 kPa. Temperature extrema are also within 0.7 K at these checkpoints. These paired values do not distinguish the schemes meaningfully at this early interval. The IAS700 limited-linear case reached a later persisted checkpoint (19.004 microseconds) than its baseline (15.334 microseconds); IAS900's limited-linear checkpoint (12.303 microseconds) is earlier than its baseline (18.188 microseconds). Runtime progression under wall caps is not a stability metric, and the compared cases do not reach the prior late instability around 0.12–0.15 ms.

This test supports only the conclusion that the isolated scheme change does not materially alter the examined early checkpoint state. It does not establish that either scheme resolves or prevents the later blow-up, and does not support convergence, load, or design claims. Evidence is in the compressed solver/dry-run logs, checkpoint-history JSON files, case bundles, and per-case `run_manifest.json`; these manifests pin mesh, geometry, generator, analyzer, solver package provenance, and all relevant control dictionaries by SHA256.
