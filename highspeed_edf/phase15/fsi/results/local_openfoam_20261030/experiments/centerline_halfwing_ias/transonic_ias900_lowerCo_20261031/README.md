# Bounded diagnostic: transonic IAS900 on the existing centerline HXT mesh

This is a diagnostic run on the 49,208-cell existing centerline half-wing mesh while the separate `/tmp/snappy-wing-probe` was active. No mesher was duplicated. The mesh is a rigid x=0..260 mm experimental half-wing with no fuselage, EDF, moving mesh, or root fillet. Source mesh SHA256: `1eeeeea4145aabd579c2d6dd209ec5bf38daefc73225b4a56d9b2c84fb8d45a6`. Geometry SHA256: `4d2a6eefd10cc547d45baadd9207218de688696730c3722ae2247bf9c86ef2e2`.

The case is IAS900 at 3,000 m, TAS 283.17196 m/s, Mach 0.861815, static pressure 70,100 Pa, static temperature 268.65 K, and +0.5° incidence about y. The imposed freestream is subsonic (Mach 0.8618); this failed run did not establish whether or where local transonic flow occurs, so that assessment remains unresolved. The prior U field had zero x component despite candidate metadata saying 0.5°; this run explicitly sets velocity to (2.47111, 0, 283.16118) m/s. It retains the tested transonic PIMPLE solver and lowers maxCo from 0.2 to 0.1. Wall cap was 1,800 s, checkpoint interval 10 steps, purgeWrite 20, and the local runner used nice +10. No paid cloud was used.

`checkMesh -allTopology -allGeometry` exits 0 and says the mesh is topologically valid, but fails two quality checks: 411 cells have determinant below 0.001, and 14 faces have interpolation weight below 0.05. Maximum non-orthogonality is 83.46° and skewness 2.774. `rhoPimpleFoam -dry-run` passes. This remains a failed strict mesh gate and cannot support design evidence.

The solver advanced for 64 s wall time (about 52 s execution time) before it was stopped at latest complete checkpoint t=5.6100292e-06 s. The bound monitor found static T=234.6..299.8 K and a calorically-perfect local total-temperature proxy of 353.6 K, above the approximately 309 K freestream total-temperature bound; max speed was 328.9 m/s. It sent SIGTERM. The wrapper recorded exit code 143; there is no normal `End` marker and no convergence claim. The fields show an early energy overshoot on the coarse/poor-quality mesh, so this is a failure diagnostic, not a usable transonic solution.
